# 所有工具共用的入口规则与提示词

规则是产品无关的。Codex、ZCode、OpenCode、Claude Code、其他 IDE/CLI 各自按实际支持的规则入口加载，不要求特定 Skill 目录、会话 API 或插件。仅把目录名叫 skill 不代表产品已经读取。

## 项目规则追加块

优先使用 `install --rules-file AGENTS.md`（或实际 Markdown 入口）追加受管短规则，重复执行不会添加重复块；不支持该入口的产品再使用下面的手工提示词。安装规则不会证明产品已读取它。

将下面内容**追加**到现有项目规则，替换两个绝对路径。适用支持 AGENTS.md 的产品；其他产品放入其实际规则文件或作为每次任务的首条提示词。不要覆盖既有规则。

~~~text
本项目允许多个独立 AI 工具同时或先后开发，共用同一 Git 仓库。
原项目目录：<原项目绝对路径>
统一协作协议：<skill目录绝对路径>/SKILL.md
统一脚本：<skill目录绝对路径>/scripts/parallel_tasks.py

开始写入前必须阅读上述协议和本项目规则，并执行 status。
新开发任务用 enter --agent <实际工具标签> --task <唯一ID>
--scope <明确文件或目录>，声明端口/数据库/缓存/容器/输出目录资源。
同一产品多个任务也分别登记；无固定协调者、无整批等待。

实际产品工作区、编辑工具路径和命令 cwd 必须指向返回的 task.path；
不能继续在原项目目录写业务代码，也不能只让终端 cd 而编辑器留在原目录。
在任务目录 guard --task <ID> --token <接续码> 后开发。
如果产品当前会话无法转移工作区，在正确目录打开可接续的会话并带入任务信息；
做不到独立目录则只允许串行写入，不能宣称并行隔离成功。

只操作自己的任务目录/分支和声明资源。禁止覆盖别的目录、
切换原目录分支、改共享 Git 配置/stash、强制清理或删除其他成果。
只读查看原目录允许，业务写入仅经 prepare/publish 审查回填。

完成必要验证后 ready 并停止写入；审查任务树后 prepare，
在独立候选目录解决冲突/验证/审查，再 publish 审查过的候选树。
配置 verification.commands 时，冲突先 resolve，再停止开发服务，
verify --reviewed-tree <候选tree> --workers-stopped 成功后才可 publish。
未配置时按项目要求人工验证；配置在 enter 时冻结。
过期候选重新 prepare，不直接覆盖原目录。其他任务无需等待。
后继依赖任务在前置 publish 成功后 enter，不能依赖仅有文字的完成声明。
真正停止全部写入者和服务后 release --workers-stopped。
没有用户授权不提交、推送、部署、删除或 stash。
~~~

新 worktree 只自带已提交文件；若 skill/AGENTS.md 尚未提交，它们未必在 task.path 存在。通过绝对路径显式读取统一协议与原项目规则，并将下面任务信息带入实际开发会话。不要未经授权提交安装文件来掩盖上下文缺失。

## 任意产品的启动提示词

~~~text
请按 <skill目录绝对路径>/SKILL.md 的通用协作协议开发。
原项目：<绝对路径>。
工具标签：<任意标签>；新任务ID：<唯一ID>。
目标与验收：<需求>。
允许修改：<具体相对文件或目录>。
资源：<端口、数据库/schema、Redis前缀、Docker名、可写目录>。
先 status 再 enter；把返回的实际 worktree 作为所有编辑和命令根目录，
guard 通过后开发。你不是仓库唯一执行者，不撤销其他工具改动。
必要验证后逐个 ready、审查、prepare、验证候选、审查、publish。
不需要等待其他任务；不自动提交。保留失败现场及尚在运行的服务信息。
~~~

## 转到实际 worktree 或重启接续

优先运行 `bundle --task <ID> --token <接续码> --format text`，脚本会生成含实际绝对路径、目标、基线、认领与资源的自包含提示词。CLI 可以使用 `launch -- <程序> <参数>` 确保启动 cwd 和任务环境；图形产品在实际目录打开并显式使用环境文件。下面是手工接续模板。

~~~text
接续已登记任务，不重新 enter：
任务ID：<id>；工具标签：<agent>；接续码：<token>。
你的实际工作目录：<task.path绝对路径>。
原项目：<source.path>；分支：<task.branch>。
基线commit：<baseline_head>；实际基线tree：<baseline_tree>。
统一协议和脚本：<绝对路径>。
目标/验收、范围、接口、资源、验证方法：<自包含内容>。

先读取协议和生效的项目规则。在上述实际目录 guard 后继续，
暂停任务先 resume --workers-stopped；确认没有旧执行者同时写这个任务目录。
新共享成果不自动拉取到进行中的目录，交付时三方合并。
不能写原项目或其他任务目录，不自动提交/推送/部署/清理。
~~~

token 应保留在该任务上下文或本机登记，避免误贴到另一个正在工作的会话。它只是协作接续码，不提供安全权限隔离。

## 用户的日常用法

分别向任意工具发“按通用协作协议做任务A/B/C”，每个新任务用新ID，各自打开返回的目录。任务可同一天开始、隔几天开始或工具重启后继续。你只需要明确需求、范围、验收，协作流程由工具执行。

如果让某工具始终打开原项目并直接修改同一目录，协议无法保证源码不被其他进程覆盖。此时先停止其他写入会话，轮流开发，或启用各产品真正支持的目录沙箱/容器后再并行。不要把普通文本规则描述成强制安全机制。
