# 多工具共用项目

共用一个本地 Git 仓库的历史，每个写入任务使用独立 worktree 和分支。工具名只是标签，不依赖产品会话、模型、插件或调度 API。同一工具多个任务也各自登记；只读分析可以共享目录。

所有工具直接写同一物理目录时，文本规则无法防止覆盖。必须实际打开任务目录；只有终端 cd 不代表编辑器切换了项目。做不到独立目录时停止其他写入者并串行开发。

## 共同约束

1. 一个任务只有一个实际写入者；所有参与者调用同一版本脚本，登记存于 Git common directory。支持持续接入和逐个交付，无统一协调者或整批等待。
2. 原目录用于查看成果、接收已审查回填。只修改自己 scope 内的代码、分支和声明资源；不切换原目录分支，不修改共享 Git 配置、其他分支或共享 stash。
3. worktree 隔离源码、HEAD 和索引，仍共享 Git 对象、默认配置及引用。端口、数据库/schema、缓存前缀、Docker 名称和可写目录另行隔离。不共享可写 node_modules、venv 或构建输出。
4. `--exclusive` 和项目 `exclusive_paths` 用于公共接口、迁移、lockfile 等独占路径。普通文件可并行开发；认领持有到明确 release，不按时间抢占。遵守 scope 和其他任务认领。
5. 规则、接续码、资源声明和锁属于协作约定，不是认证或操作系统沙箱。资源登记不创建数据库，也不持续绑定端口；实际连接和命名隔离必须落实。
6. 不自动提交、推送、部署、stash、强制清理或删成果；用户已有明确授权继续有效。只汇报实际验证结果。

## 接入与启动

读取 [操作说明](references/worktree.md)，首次先运行 `--help`。需要 Git、Python 3.9+；仅使用标准库。Windows 使用 `pwsh.exe`（PowerShell 7）。

向首次使用者讲解或交接时，参考 [小白使用手册](references/beginner-guide.md)，涵盖概念、逐步操作、出错恢复和归档清理。释放资源不会删除 worktree；当前没有自动清理协议历史的命令。

可用 `install` 把完整 Skill、默认配置和短规则安装到目标项目。默认追加 AGENTS.md；其他 Markdown 入口用 `--rules-file` 明确指定。保持原规则，不假定产品自动发现 Skill。不支持规则文件的工具使用 [通用提示词](references/agent-prompts.md)。安装文件需按项目流程审查并纳入基线，脚本不替用户提交。

开始任务：检查 Git 状态、实际分支、HEAD、worktree 列表，以及生效 AGENTS/README。按环境约定使用图谱定位相关代码，明确目标、验收、scope、接口、依赖、资源及验证方式，再登记：

~~~powershell
python '<统一Skill绝对路径>/scripts/parallel_tasks.py' --repo '<原项目绝对路径>' enter --agent '<工具标签>' --task '<唯一ID>' --goal '<目标及验收>' --scope '<相对文件或目录>' --resource port:auto
~~~

`enter` 返回目录、分支、接续码和实际基线，并生成自包含 handoff。用 `bundle --format text` 重新获取提示词，携带到实际开发会话；协议和原项目规则用绝对路径读取，避免未提交规则在新 worktree 中缺失。

图形产品在返回的 task.path 打开工作区；CLI 可用 `launch -- <可执行程序> <参数>` 在该目录启动，注入任务环境并记录退出码。launch 不自动发送提示词、不验证产品编辑沙箱，也不停止外部服务。详见 [项目配置](references/configuration.md)。

在任务真实 cwd 执行 `guard` 后开发，重启接续也先 guard。暂停任务先 resume；冻结后继续修改先 reopen。优先复用无人写入且确实适合的原生 worktree，用 `enter --worktree` 登记；否则由脚本创建。

## 开发与交付

遵循实际项目规则，不撤销既有修改，不扩大范围。使用已有依赖、构建和用户约定；本环境默认不新增测试文件、不执行前端测试套件，未人工验证的前端如实说明。

后来任务以最新已提交代码及协议已回填的未提交成果为基线；原目录未知改动保留，不复制给新任务，且阻止回填。进行中的任务不自动拉取新成果；依赖前置结果时，等前置 publish 成功再 enter。

每个任务独立执行：

1. 完成必要验证，`ready` 冻结树；它不修改真实索引，也不生成 commit。停止写入，审查基线到任务树的实际 diff，核实验证证据。
2. `prepare --reviewed-tree <任务tree>` 在独立候选上三方集成最新共享成果。候选应用仅持本任务锁，其他任务可继续操作；冲突现场保留，不阻塞其他任务。
3. 在候选目录审查最终 diff，验证接口、数据和业务兼容。冲突手动解决并暂存；`inspect` 获取实际树，验证及审查后 `resolve`。
4. `publish --reviewed-tree <候选tree>` 串行回填原目录暂存区。HEAD/基线过期或原目录出现未知内容时拒绝，重新 prepare、验证及审查，不能覆盖新成果。
5. 真正停止任务全部写入者及服务后 `release --workers-stopped`。成果、目录和分支保留；未交付任务变 parked，以后 resume 重新检查资源和认领。

ready 不代表验收通过，publish 不代表已提交或部署。Git 没有文本冲突仍可能存在业务冲突。旧候选和快照保留，不自动删除。

## 诊断与中断

`status --format table` 查看状态及下一步，`events` 查看审计。日志不记录任务接续码、环境值或完整启动参数。`doctor` 只读核查目录、分支、候选冲突、任务环境、锁和中断。

内核文件锁随进程退出释放，锁文件永久保留；等待超时不等于可以抢占。旧目录锁需停止旧脚本、核实 owner 主机/PID，并使用 doctor 指纹执行 recover-lock；不混用旧新版本。

`recover` 根据真实内容恢复 creating/preparing/publishing 或中断启动记录。额外修改时保留现场；不能证明旧候选成功时创建新候选重新审查。具体条件见操作说明。`--workers-stopped` 是执行者确认，不能证明程序已停止全部子进程。

汇报任务实际目录、状态、是否回填、验证结果、占用资源及未完成项。只验证协议脚本时，不宣称已验证各产品自动加载规则、目录沙箱或真实业务集成。
